# 问题分析：声音跳转与句子点击不对应 / 单句循环不生效

> 版本：2026-09-16 · 状态：进行中 · 关联：`30f5a63`、`d44359f` 的播放器修复

## 现象

用户实测（本地 Windows 环境）反馈两个问题依然存在：

1. **声音跳转与鼠标句子点击时间不对应**：点击某句后，声音播放的位置与点击的句子时间戳不一致，听到的内容与高亮句错位。
2. **单句循环功能不生效**：点击「单句循环」按钮后，没有进入当前句的循环播放。

## 复现步骤

1. 启动后端（`backend/main.py`，端口 8000）并打开前端（`frontend/index.html`）。
2. 打开任一素材（如 m2），播放音频。
3. 鼠标点击第 3 句（时间戳 00:16 起）→ 观察声音位置与高亮句是否一致。
4. 播放中点击工具栏「单句循环」→ 观察是否跳回当前句首并循环。

## 当前排查状态

> 注意：在自动化验证环境（本环境 Chromium 无头 + 重新合成后的 m2）中，上述两个场景均已验证通过：
> - 点击第 3 句后 `currentTime≈16727ms`，高亮 `00:16–00:25`，一致；
> - 单句循环开启后跨过句末自动回卷句首（多次采样 0 次越过句末），关闭后恢复连续播放。
>
> 用户环境仍复现，说明存在**环境差异或未覆盖场景**，需按下列假设逐项核对。

### 已修复项（提交 `30f5a63` / `d44359f`）

| 提交 | 内容 |
|---|---|
| `30f5a63` | 时间戳链路重构：逐句归一化 WAV → 解码实测时长 → filter concat 统一重编码；消除 mp3 padding 累积偏移与 gap 帧对齐误差 |
| `d44359f` | 单句循环开启即跳当前句首并回卷；合成后 `<audio>` 强制重载，消除高亮与声音错位 |

### 用户环境复现的可能原因（按可能性排序）

1. **素材未重新合成（最可能）**
   - 时间戳修复只作用于**重新合成后**的音频。旧素材的 mp3 由旧链路（`-c copy` 拼接）生成：物理时长与时间轴存在每句十几~几十毫秒的累积偏移（m2 实测物理 35.76s vs 时间轴 35.58s）。
   - 若用户未对素材执行「生成音频」（步骤 2），点击句子跳转仍按旧音频物理位置走，错位依旧。
   - **核对方法**：对素材重新合成一次后重测；或查看 `materials` 接口中 `total_duration_ms` 与音频实际时长是否一致。

2. **前端 / 后端未更新到最新代码**
   - 前端是单文件 `index.html`，若浏览器缓存了旧版本，单句循环点击逻辑（开启即跳句首）不生效；
   - 后端若未重启（未加载新 `main.py`），合成链路仍是旧实现。
   - **核对方法**：硬刷新（Ctrl+F5）前端；确认后端进程为最新代码后重启。

3. **浏览器对同 URL 音频的缓存**
   - 即使重新合成，若 `<audio>` 元素复用旧缓冲（`d44359f` 已加强制重载），旧版本前端下仍会播放旧文件内容 + 新时间轴 → 错位。
   - **核对方法**：确认前端已包含 `synthesizeAudio` 成功后的 `pb.load()` 重载逻辑。
