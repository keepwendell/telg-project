## 二、P0 — 互斥与数据正确性

### P0-1 合成中切换素材 → 合成完成时界面与数据错乱

- **位置**：`synthesizeAudio()` 异步闭包（~3955 行）完成段
- **现象**：合成期间用户点击其他素材（`loadMaterial` 切走 `state.current`）；合成完成后无条件执行 `renderMaterial(); play();`——`renderMaterial` 渲染的是**当前（新）素材**，`play()` 播放的也是新素材；而 `art`（闭包）仍是旧素材。结果：音频文件已为旧素材生成，但界面高亮/播放落在新素材上，二者不一致；若新素材未合成，还会弹出误导性的"Audio ready — playing from sentence 1"。
- **修复建议**：完成段先判断 `state.current && state.current.id === art.id`：
  - 一致 → 现有 render + play 流程不变；
  - 不一致 → 仅把 `art` 状态更新写回 library（`art.meta.audioReady=true` 等已在闭包对象上生效），`renderLibrary()` 刷新列表，toast "音频已合成"；不渲染、不播放。

### P0-2 Test Data 种子素材（m1/m2/m3）播放必失败

- **位置**：`MOCK_MATERIALS`（~1925 行）`audio_url: '/mock/audio/m1.wav'`；后端无 `/mock/audio/*` 路由
- **现象**：种子素材 `meta.audioReady` 字段缺失（`undefined !== false`）→ 播放按钮不禁用；`play()` 不拦截 → `audio.src=/mock/audio/m1.wav` → 404 → `play().catch` 静默失败，界面无音频无进展。
- **修复建议**（二选一）：
  - a. 种子素材统一标注 `audioReady: false`（与草稿一致，点击合成后才可播）；或
  - b. mock 模式下播放走纯模拟路径（`mockMode()` 时 `play()` 直接置 `state.playing=true`，由 `tick()` 模拟分支推进 `state.time`，不依赖真实 `<audio>`）。

## 三、P1 — 可用性（禁用缺失）

### P1-1 播放器控制组未随 audioReady 禁用

- **位置**：`renderPlayerBar()`（~4270 行）；播放器 6 个控制按钮（prev / back10 / play / fwd10 / next / bookmark + 右侧 loop）；**transcript 行内 `[data-act="sloop"]` 单句循环按钮**
- **现象**：`btn-pb-play` 与 `btn-pb-subs` 已正确禁用 ✓；但 **prev / back10 / fwd10 / next / bookmark / loop** 在未合成素材上仍可点击，`seekSentence`/`seek` 静默 return，无任何反馈。
- **句级 sloop 附加问题（状态污染）**：transcript 行内单句循环按钮点击时先执行 `state.loop = true; syncLoopUI();` 再 `seekSentence`——在未合成素材（无时间戳）上 `seekSentence` 防御 return，但 **`state.loop` 已被置 true**：footer 循环按钮显示"on"，合成后首次播放会意外进入单句循环，用户无从察觉原因。
- **修复建议**：
  - `renderPlayerBar` 中对全部播放控制按钮统一 `disabled = art.meta.audioReady !== true`（含 `.disabled` 灰化样式 + cursor），或统一点击 toast "语料未合成，请先 Set Voice & Synthesize"；
  - transcript 渲染（`transcriptHTML`）对 sloop/bookmark 行内按钮同样按可播放性加 `disabled`；
  - sloop 点击改为"先校验可播放，再改状态"——`if (!isPlayable) return;` 置于 `state.loop=true` 之前。

### P1-5 无素材时 `btn-voice`（Adjust）→ 弹窗直接崩溃

- **位置**：`openTTSModal()`（~3859 行）/ `openAdjustModal()`（~3771 行）
- **现象**：无素材（`state.current` 为空）时 `btn-voice` 仍可点 → `openTTSModal` 首行 `$('tts-material-title').textContent = art.meta.title` **TypeError 崩溃**（`openAdjustModal` 的 `art.meta.saved` 同样无保护）。对比 `openPublishModal`/`openPlModalFor`/`startRenameHead` 均有 `if (!art) return`——Adjust 入口是唯一漏网之鱼。
- **修复建议**：`openTTSModal` / `openAdjustModal` 首行加 `const art = currentArtifact(); if (!art) return;`；同时 `btn-voice` / `btn-edit-audio` 在无素材时禁用（并入 P1-1 的统一禁用逻辑）。

### P1-2 生成 / 合成进行中按钮无视觉禁用

- **位置**：`runGenerate()` 有 `state.generating` 锁；`synthesizeAudio()` 有 `state.synthesizing` 锁
- **现象**：生成中重复点击 `btn-generate` 无响应（锁生效）但按钮不变灰、无 loading 态；`btn-synth` 已禁用 ✓ 但 `btn-voice` / `btn-refine` / `btn-publish` 在合成中仍可点开弹窗。
- **附加（本次复核）**：**`refineGenerate`（refine 应用）只查 `state.generating`，不查 `state.synthesizing`** → 合成进行中点 refine 应用会再次触发语料生成，与后台合成任务并发冲突（两个任务同时写 library/UI）。
- **修复建议**：
  - `state.generating || state.synthesizing` 期间：`btn-generate` disabled + "Generating…"；生成面板外的主操作按钮（refine / voice / edit-audio / publish）统一 disabled；
  - `refineGenerate` 开头补 `if (state.synthesizing) return;`（与 `synthesizeAudio` 的 `if (state.generating) return;` 对称）。

### P1-3 空 topic 可触发生成

- **位置**：`collectParams()` → `topic: $('topic-input').value.trim()`
- **现象**：topic 清空后点 Generate，后端 422 或模板生成空主题素材，无前置校验。
- **修复建议**：`topic-input` input 事件实时校验——空值禁用 `btn-generate`（灰化），并显示"请输入主题"提示。

### P1-4 键盘快捷键对未合成素材无反馈

- **位置**：`onKey` J/K/R/空格
- **现象**：空格已 toast ✓；J/K/R 在未合成素材上静默无效。
- **修复建议**：与 P1-1 合并——快捷键入口统一走同一"可播放性"校验，未合成时 toast 一次。
