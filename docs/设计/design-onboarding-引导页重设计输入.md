# Onboarding 业务背景与页面逻辑要求（供引导页现代化重设计）

> 用途：作为第三方 LLM 重新设计 TELG 欢迎/引导页的**输入规格**。本文只描述业务背景、流程与硬性逻辑约束，视觉方向交由设计方发挥（现代工具类产品风格）。
> 基线文件：`frontend/onboarding.html`（当前实现，可打开参考现有交互与数据契约）。

---

## 一、产品背景（为什么有 Onboarding）

**TELG = Technical English Listening Generator**：面向技术研发人员的参数化技术英语听力素材生成器。

- 用户输入一个技术主题 → 系统用真实 LLM 生成一段**真实工作场景的技术英语对话**（含逐句中英文本、词汇、问题、讲义）→ 用 TTS 逐句合成音频并拼接 → 得到可逐句跟读/精听的听力素材。
- 技术栈：FastAPI 后端（`backend/main.py`）+ 单文件 HTML 前端（原生 JS，无构建工具）。
- 前端分两个页面（同源、共享 localStorage）：
  - `frontend/index.html` —— 主页面（生成/播放/管理）
  - `frontend/onboarding.html` —— 欢迎 + 首启引导（本设计的对象）

**为什么必须有引导**：新用户首次打开是空界面——无登录、无画像、无默认方向。引导承担四件事：

1. 建立本地账号（登录态）；
2. **强制配置真实 LLM**（后续所有语料生成都依赖它，不可跳过）；
3. 采集个性化档案（职位角色、练习领域、语言方向、每日时长目标）——档案驱动主页面新建素材弹窗的领域/角色/场景默认选项，并注入生成 Prompt；
4. 由 LLM 生成**初始推荐**（领域/角色/场景列表），用户确认后可编辑，作为产品默认起点。

引导完成 → 进入主页面。之后主页面可直接打开；未登录或未完成引导的用户访问主页面会自动跳回引导页。

## 二、引导流程（现状 4 步，逻辑需保留）

| 步骤 | 名称 | 内容 | 进入下一环节的条件 |
|---|---|---|---|
| 1 | **欢迎 / 账号** | 品牌欢迎页；新用户注册 / 老用户登录（本地账号，SHA-256 哈希存 localStorage）；游客入口 | 登录或注册成功 |
| 2 | **LLM 配置** | Provider 预设下拉（DeepSeek / 豆包 / Kimi / OpenAI 兼容…）+ Base URL + Model + API Key（密码框 + 可见切换） | **点击「下一步」即执行连通测试**：转圈验证 → 通过自动进入下一步；失败显示原因并停留 |
| 3 | **个性化问卷** | 4 项：① 角色/职位（自由输入，可空）② 主练习领域（自由输入，必填）③ 语言方向（chip 单选：中英可选；日/德等标注「开发中，敬请期待」并禁用）④ 每日听力时长目标（数字，必填） | 领域与时长必填校验通过 |
| 4 | **档案确认** | 摘要展示；LLM 生成结果（角色画像 / 领域档案 / 语气建议 / 推荐领域·角色·场景）可编辑、可重新生成；也可手动填写 | 点击「确认并进入」 |

**进入主页面时写入（数据契约）**：

```
localStorage:
  telg-auth           { username, salt, passHash, session }   // 登录态
  telg-accounts       [{...}]                                 // 本地账号列表
  telg-onboarding     { done: true, at }                      // 引导完成标记
  telg-settings       { llm, profile, goalMin, recommendations, ... }  // 档案+配置
  telg-profile-answers{ role, domain, language, minutes }     // 问卷原始回答

后端接口（同源 /api/v1）:
  POST /config/test-llm                // LLM 连通测试（返回 { ok } 或错误）
  POST /config/onboarding/generate     // LLM 生成档案+推荐（无 key 返回明确错误）
```

## 三、页面逻辑硬约束（不可违反）

1. **LLM 不可跳过（正式逻辑）**：必须配置真实 LLM 且连通测试通过，才能进入问卷与主页面。
   - 开发/测试期可保留「跳过 — 仅测试用」入口（正式发布移除）；跳过路径下问卷提交不调 LLM，直通档案确认页（手动填写）。
2. **无独立测试按钮**：连通验证内置于「下一步」——点击后按钮进入转圈 busy 态，通过则继续，失败则本步停留并展示原因（API Key 无效 / 网络不通等）。
3. **问卷必填校验**：领域、每日时长必填；角色可为空；语言仅中英可选。
4. **档案可编辑**：确认页允许手动修改所有字段；LLM 生成结果与用户修改共存，保存时以用户最终内容为准。
5. **数据互通**：引导页与主页面完全共享 localStorage；引导完成标记（`telg-onboarding.done`）是主页面放行的唯一依据。
6. **技术形态**：单文件 HTML（内联 CSS/JS、原生 JS、无构建）、支持深浅主题（`data-theme` + CSS 变量）、中英双语（`data-i18n` 机制）、与主页面视觉体系同源（共享 CSS 变量与组件样式基调）。
7. **可独立调试**：`http://127.0.0.1:8000/onboarding.html` 可直接打开走完整流程；主页面 `index.html` 负责跳转逻辑。

## 四、设计期望（用户诉求，供设计方发挥）

- **定位**：现代专业工具类产品的首启体验，对标 OpenCode / Linear / Cursor 等产品的欢迎与引导页质感。
- **观感**：不再是当前的朴素弹窗/表单堆叠；要求卡片更大、布局统一、层级清晰、留白与呼吸感到位；标题层级可读；深色与浅色主题下都美观。
- **分步引导**：四步之间过渡自然（可保留「下一步/上一步」或采用分步进度条），每步信息聚焦、不拥挤；问卷步骤各问题块视觉整齐。
- **反馈质感**：加载/验证用转圈而非呆板文字；成功/失败有清晰的视觉区分（颜色 + 图标 + 文案），错误文案可读不堆代码。
- **响应式**：桌面为主，窄窗口（如 960px 以下）不破版；弹窗/页面在窗口缩放时保持居中与合理尺寸。
