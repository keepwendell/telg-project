## 1. 背景与目标

### 1.1 现状

- 领域（Automotive / Embedded / AD / Robotics / Power Electronics）、角色、场景为**硬编码下拉**，产品被锁定在"汽车+嵌入式"小圈子。
- 新用户拿到软件是**空界面**：无引导、无画像、无默认方向，第一体验成本高。
- 用户画像（职位、练习领域、语言方向、时长目标）无采集入口，设置中仅有时长目标（Training Goal）。
- 数据持久化为单机 SQLite + localStorage + 音频目录，无备份/迁移能力。

### 1.2 目标

1. **领域开放**：任意工程领域可生成（半导体/新能源/AI/医疗/金融等），LLM 按领域档案约束术语与场景。
2. **首启引导**：新用户 3 段式引导（LLM 就绪 → 画像问卷 → 档案确认），60 秒内获得可用起点。
3. **学习档案**：用户画像（职位/领域/语言/时长/场景）结构化存储，驱动生成默认值与 prompt 注入，可在设置中查看/修改/重置。
4. **持久化可演进**：现阶段补备份/迁移能力，未来平滑扩展多端同步。

## 2. 设计一：领域档案（Domain Profile）

### 2.1 数据模型

领域不是单个字符串，而是"档案"：

```json
{
  "id": "semiconductor",
  "name": "Semiconductor",
  "builtin": true,
  "description": "晶圆制造、良率、工艺与设备工程",
  "inject": "术语惯例：lithography, yield, etch, CMP, OOC...；典型场景：工艺评审/失效分析/设备验收；角色画像：Process Engineer / Yield Engineer / Equipment Vendor"
}
```

- **预设库**：内置 5-8 个领域档案（汽车、半导体、新能源、AI/软件、医疗设备、金融科技、航空航天、通用工程）。
- **自定义**：用户创建（双路径，见 2.2），`builtin=false`。
- **注入点**（一份档案驱动三处）：
  1. 生成 prompt：领域专家角色 + 术语/场景/角色约束注入
  2. 生成面板默认值：domain/role/scenario 预填
  3. 素材组织与学习统计：按领域聚合/筛选

### 2.2 双路径创建

| 路径 | 交互 | 适用 |
|---|---|---|
| A · LLM 辅助（默认） | 输入名称+可选描述 →「生成档案」→ LLM 扩写结构化草稿（描述/术语建议/场景建议/角色画像，分区块可编辑）→ 确认保存 | 用户只想给个名字，质量交给 LLM 扩写 |
| B · 手动（兜底） | 输入名称+描述 →「直接保存」 | LLM 不可用 / 用户已写完整 / 仅作轻量标签 |

- 生成的草稿**不是不可变结果**，是"被确认的草稿"，各区块可独立编辑。
- LLM 生成失败/不可用 → 自动降级路径 B，不阻塞。
- 内置档案直接用，不走生成流程；已创建档案可再编辑/重新生成。

## 3. 设计二：首启引导（欢迎页 + 本地账号 + 四段式）

> 核心原则：零压力、可跳过、渐进披露。第一体验目标 = 60 秒内听到一段自己领域的技术对话。
> 决策（2026-09-17）：先使用**本地账号**验证与测试，预留云端迁移路径（AuthAPI 契约不变，仅换实现）。

### 3.0 阶段 0 — 欢迎页 + 本地账号

**欢迎页**（首次打开 / 未登录）：
- 品牌与产品一句话说明 + [开始使用]；全屏覆盖层，与主界面解耦。
- 分流：已有本地账号未登录 → 登录表单；首次 → 创建账号表单；已登录（记住态）→ 直接进入主界面。

**本地账号**（`localStorage: telg-auth`）：
```json
{ "username": "wendell", "passHash": "sha256(salt+password)", "salt": "…", "created_at": 1789…, "session": true }
```
- 密码用 `crypto.subtle.digest(SHA-256, salt+password)` 加盐哈希，仅存哈希不存明文；本机登录态用 `session` 标记（退出登录即清除）。
- 提供「游客模式」跳过入口（数据仍存本机、不绑定账号），登录/注册/登出入口在设置页 About Tab。

**AuthAPI 契约**（云端迁移时仅换实现，前端调用点不变）：
```js
AuthAPI = {
  register({username, password}) -> {ok, user}      // 本地：写入 telg-auth；云端：POST /auth/register
  login({username, password})    -> {ok, user}      // 本地：比对哈希；云端：POST /auth/login → token
  logout()                       -> {ok}            // 本地：清 session；云端：POST /auth/logout
  current()                      -> user | null     // 本地：读 telg-auth.session；云端：GET /auth/me
}
```
> 本地实现内置在 index.html；云端实现（后端用户表 + token + 数据隔离 + 同步）属多端阶段，见 §5.3。

### 3.1 阶段 1 — LLM 就绪引导

- 自检 LLM 配置（provider / base url / key），未就绪进入引导卡片：
  - 选提供商 → 填 base url + key → 「连接测试」→ 显示自检结果（可用 / 失败原因）
- 提供「暂用测试数据」跳过入口（mock 兜底），同时提示档案生成功能受限。

### 3.2 阶段 2 — 画像问卷（5 问 + 时长，约 1 分钟）

每题一屏，快捷选项 chip 点击即选 + 自由输入，可后退/跳过：

| # | 问题 | 快捷选项（chips） | 输入形态 | 产出落点 |
|---|---|---|---|---|
| 1 | 你的角色/职位？ | 软件工程师 · 硬件工程师 · 算法工程师 · 测试工程师 · 项目经理 · 学生 | 自由输入 + chip | profile.role |
| 2 | 主要练习领域？ | 汽车电子 · 半导体 · AI/软件 · 新能源 · 医疗设备 · 金融科技 | 自由输入 + chip | 首选领域（档案） |
| 3 | 语言方向？ | 中英 · 日英 · 其他 | chip 单选 | profile.languages |
| 4 | 每日练习时长？ | 15 · 30 · 45 · 60 · 90 分钟 | chip 单选 | **映射现有 cfg-goal-min（唯一来源）** |
| 5 | 练习场景？（多选） | 技术面试 · 会议汇报 · 团队协作 · 供应商沟通 · 课堂教学 | chip 多选 | profile.scenarios |

> 时长目标**不在档案中重复存储**——问卷第 4 题直接写入现有 Training Goal（cfg-goal-min），保证唯一来源。

### 3.3 阶段 3 — LLM 生成档案 + 确认

- LLM 结合 5 项原始回答生成结构化档案：

```json
{
  "role": "控制系统算法工程师",
  "primary_domain": {"name": "半导体", "description": "…", "focus": "…"},
  "languages": ["en", "zh"],
  "scenarios": ["technical_interview", "team_collab"],
  "focus_areas": ["…"],
  "tone_preference": "…"
}
```

- 分区块可编辑 → 确认保存。
- **降级**：LLM 不可用/失败 → 直接保存原始回答文本，提示"稍后在设置中可重新生成档案"。
- 原始回答持久化（localStorage `telg-profile-answers`），供"重新生成"复用。

### 3.4 引导状态

- `localStorage: telg-onboarding = {done, llmReady, profileReady}`；跳过即完成。
- 引导完成后进入主界面（空态三动作：示例素材 / 引导新建 / 导入）。

## 4. 设计三：学习档案管理与设置合并

### 4.1 Study Tab 结构（合并后）

```
Study
├─ 训练目标（保留现有）  每日时长目标下拉（cfg-goal-min）+ 学习统计
├─ 学习档案（新增）      职位 · 领域 · 语言 · 场景
│    └─ 摘要卡片 → 编辑 → 重新生成 / 清除
└─ （时长目标只此一处，档案不重复采集）
```

### 4.2 档案管理三操作

| 操作 | 语义 | 交互 |
|---|---|---|
| 查看 | 摘要卡片：职位画像、首选领域（名称+描述）、语言方向、时长目标、场景标签 | 只读，一屏可见 |
| 修改 | 分区块编辑（职位/领域描述/术语/场景/角色/语言/场景） | 与创建时草稿编辑形态一致；保存即生效，标记"已手动修改" |
| 重置 | ① 重新生成（基于原始问卷回答重新调 LLM 扩写为草稿 → 确认替换）② 清除档案（回未配置态，可重走问卷） | 重置前确认弹窗（沿用交互原则：操作名 → 对象名 → 确认键） |

### 4.3 联动

档案变更 → 生成面板默认领域、学习统计目标、prompt 注入实时使用新值。

## 5. 数据持久化分阶段

### 5.1 数据分层

| 层 | 数据 | 特点 | 现状存储 |
|---|---|---|---|
| 用户状态 | 设置、学习档案、收藏、学习统计、播放列表 | 轻、高频、结构化 | localStorage + SQLite |
| 内容资产 | 语料 JSON、MP3 音频、素材元数据 | 重、可再生成、体积大 | SQLite 索引 + `storage/audio/` 文件 |

### 5.2 阶段规划

| 阶段 | 内容 | 说明 |
|---|---|---|
| **现在（单机）** | 维持 SQLite + 音频目录；补 `.telg` 素材包导出/导入（语料 JSON + 音频打包）、设置一键导出；示例素材做成内置包随应用分发 | 架构不动，补迁移与备份能力 |
| **将来（多端）** | 用户账号 + 同步服务；内容资产对象存储（素材 hash 去重）、用户状态 DB 同步 + 本地缓存（离线可用、联机合并） | local-first 标准形态；iOS/macOS App 前提 |
| **全托管（多用户）** | Postgres + 对象存储 + CDN | 现阶段过度设计，不排期 |

**本地 → 云端账号迁移路径**（决策：先本地验证，后续迁移）：
1. 后端新增用户表 + `/auth/register|login|logout|me` + token；`telg-auth` 哈希算法不变，迁移时一次导入。
2. 前端 `AuthAPI` 四个方法实现从 localStorage 换成服务端调用；调用点（欢迎页/设置/登出）零改动。
3. 用户数据（档案/素材/统计/播放列表）绑定 user_id；本地数据提供「合并到账号」入口。
4. 前端 `CONFIG.apiBase` 与鉴权头由后端下发，跨设备同步随账号体系完成。

### 5.3 关键约束

前端 API 契约（`/api/v1/materials/*`）是稳定边界，后端 SQLite → Postgres 只影响后端一层，前端无需改动。现阶段不为未来迁移做任何改造。

## 6. 接口与数据落点

### 6.1 新增接口

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/v1/profile/generate` | POST | 输入问卷原始回答 → LLM 生成结构化档案（JSON schema 校验 + 重试，复用 LLM 链路） |

### 6.2 前端存储

| 键 | 内容 |
|---|---|
| `telg-settings.profile` | 学习档案（结构化，含原始回答引用） |
| `telg-settings.recommendations` | 推荐设置（问卷 + LLM 生成的领域/角色/场景，可增删改） |
| `telg-settings.domains` | ~~领域档案集合（预设 + 自定义）~~ **已废弃（2026-09-17）**：设置页不再展示/管理，旧自定义项一次性并入 `recommendations.domains`，内置领域库仅作兜底 |
| `telg-profile-answers` | 问卷原始回答（供重新生成） |
| `telg-onboarding` | 引导状态 |
| `telg-auth` | 本地账号（username + 加盐哈希 + 登录态） |

- `cfg-goal-min`：时长目标唯一来源，问卷第 4 题写入。
- 生成面板 domain 默认值 = 推荐设置的首个领域；无推荐时回退内置领域库（BUILTIN_DOMAINS）。
- ~~领域档案 `inject` 注入 LLM system prompt~~ **实现变更（2026-09-17）**：设置页独立的「领域档案」区块已并入「推荐设置」（由问卷 + LLM 生成的个性化推荐统一管理，内置预设不再回显）；领域术语知识注入生成 prompt 仍未实现（见 roadmap 事项 3）。

## 8. 风险与开放问题

1. **自定义领域术语质量**（LLM 幻觉/术语不准确）：领域档案 `inject` + 生成后术语自查指令缓解；需用 3 个非预设领域抽样人工核验（roadmap 事项 3 已有验证计划）。
2. **引导流失**：问卷 5 问控制在 1 分钟内，全部可跳过；首启"暂用测试数据"降级路径保证不卡死。
3. **档案与旧数据兼容**：已有素材 domain 为旧标签，领域档案库不含旧值时按"通用工程"兜底；播放列表/统计不受影响。
4. **多语言（日语等）**：与档案中的语言方向联动，落点见 roadmap 事项 4，本规划不展开。
5. **开放问题**：档案"重新生成"是否保留历史版本（对比）？——暂定覆盖替换 + 手动修改标记，不做版本历史，需求明确后再补。
6. **云端账号时机**：已决策先本地账号（P2a），云端迁移路径见 §5.3；触发时机＝iOS/macOS 多端需求明确后，不提前排期。
