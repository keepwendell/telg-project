# Scenear 前端架构重构规划

**版本**：v1.0
**状态**：执行中
**范围**：`frontend/` 整体重构（单 HTML → React 工程）
**前置版本**：v0.1.1（MVP，功能基线）

---

## 1. 背景与动机

当前前端是单文件 `frontend/index.html`：

| 指标 | 现状 |
|---|---|
| 文件规模 | 468KB / 7507 行 |
| JS | 5344 行原生 JS，无类型 |
| 状态 | 全局 `state` 对象，495 处直接读写 |
| DOM | 294 个函数、190 处手动事件委托，拼 HTML 字符串渲染 |
| i18n | 864 个 key 硬编码在两个大字典 |

**已暴露的痛点**：
- 无类型保护，字段名写错运行时才崩（`classList of undefined`、`depth/vocabDensity` 语义错位）
- 改 DOM 结构容易漏（字符串模板改一处误删一行）
- 单文件导航困难，跨模块影响靠人肉

**三个即将到来的需求，放大了这些痛点**：
1. 逐个弹窗/界面做 UI 优化
2. 状态驱动的动效细化（弹窗转场、句子高亮过渡）
3. 后续套 Tauri 出桌面端 APP

## 2. 目标

| 目标 | 衡量标准 |
|---|---|
| 摆脱单文件 | 模块化工程，每个弹窗/面板独立文件 |
| 状态驱动 UI | Zustand 单一数据源，界面/动画自动跟随 |
| 类型安全 | TypeScript，数据模型对齐后端 Pydantic |
| 组件化 | 弹窗/面板=独立组件，支撑逐个 UI 优化 |
| 桌面端就绪 | 标准 Vite 工程，Tauri 可直接套壳 |
| 功能不丢 | 现有 v0.1.1 全部行为保留，e2e 回归通过 |

## 3. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 构建 | Vite | HMR、Tauri 标准 |
| 框架 | React 18 | 状态驱动 UI + 动画生态 |
| 语言 | TypeScript | 消灭运行时 undefined |
| 状态 | Zustand | 替代全局 state 对象 |
| 路由 | React Router | Library / Player / Generator |
| 样式 | Tailwind CSS | 设计 token 集中，写样式快 |
| 组件库 | shadcn/ui | Radix 底层，代码可定制，不锁死 |
| 图标 | lucide-react | 替换现有内联 SVG |
| 动效 | motion（framer-motion） | spring 物理感，弹窗转场/列表过渡 |
| 动效补充 | auto-animate | 列表/布局位移动画零配置 |

## 4. 设计语言方向

**苹果 HIG 为主 + OpenCode 工具感点缀**：

- 主体：毛玻璃质感（`backdrop-filter: blur`）、大圆角、柔和阴影、系统字体、spring 动效
- 点缀：mono 字体用于时间戳/难度标签/快捷键，深色为主、中性色克制

设计 token 集中在 `src/shared/tokens/`，明/暗双主题。

## 5. 目标目录结构

```
frontend/
├── index.html
├── package.json / vite.config.ts / tsconfig.json / tailwind.config.ts
├── src/
│   ├── main.tsx / App.tsx / router.tsx
│   ├── core/
│   │   ├── api/               # fetch 封装，对齐后端路由
│   │   ├── audio/             # TTS 播放引擎（现有逻辑原样搬）
│   │   ├── i18n/              # zh.ts / en.ts（864 key 拆分）
│   │   ├── store/            # Zustand: player / material / settings
│   │   └── types/            # Material / Artifact（对齐 Pydantic）
│   ├── features/              # 按界面边界拆——UI 优化主战场
│   │   ├── library/           # 素材库列表
│   │   ├── generator/         # 新建素材弹窗
│   │   ├── refine/           # 重新生成弹窗
│   │   ├── player/           # 播放条 + transcript + 旁白卡
│   │   ├── quiz/             # Quiz 面板
│   │   ├── vocab/ patterns/  # 词汇/句型面板
│   │   └── settings/         # 设置面板
│   └── shared/
│       ├── components/        # 通用按钮/弹层/下拉（shadcn）
│       └── tokens/           # 设计变量
```

## 6. 迁移阶段

**原则：数据模型先行，逐模块替换，每步可回滚**

| 阶段 | 内容 | 验收 |
|---|---|---|
| P0 | Vite + React + TS 骨架跑通，装依赖 | `npm run dev` 空页能开，`tsc` 过 |
| P1 | types / api / i18n / audio 引擎迁入 | 播放链路 e2e 不依赖 UI 可验证 |
| P2 | Library → Player → Generator 页面组件化 | 对应 e2e 过 |
| P3 | settings / refine / quiz / vocab / patterns 面板 | 面板交互 e2e 过 |
| P4 | 接 motion 动效（弹窗转场、句子高亮） | 视觉走查 |
| P5 | 删旧 index.html，切主入口 | 全量 e2e 过 |

## 7. 风险与应对

| 风险 | 应对 |
|---|---|
| 音频引擎与 DOM 强耦合 | P1 单独抽 audio engine，先不动 UI |
| 迁移期间双轨 | 新工程独立目录，旧文件只读，P5 才切入口 |
| i18n 864 key | 字典 JSON 化，自动拆分 zh/en |
| 功能回归 | 每模块迁完跑对应 e2e，不追求一次全过 |

## 8. 节奏预估

- P2–P3：3–5 天（主体工作量）
- P4–P5：2 天
